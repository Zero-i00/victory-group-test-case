# Frontend — Архитектурные решения (DentistAm)

## Почему Next.js, а не React + Vite

Главная задача лендинга клиники — быть **найденным в поиске** и **загружаться мгновенно**. Оба требования упираются в
одно: HTML с контентом должен приходить с сервера, а не собираться в браузере после загрузки JS-бандла.

### Что конкретно даёт Next.js

**SEO.** Поисковые боты (и особенно медленные краулеры) получают полностью готовую разметку в первом HTTP-ответе.
Названия услуг, имена врачей, тексты секций — всё индексируется без исполнения JavaScript. При SPA на Vite краулер видит
пустой `<div id="root">` до тех пор, пока не выполнит JS, что ненадёжно.

**Core Web Vitals / Lighthouse.** SSR устраняет FOUC и задержку первого рендера:

- **LCP** — изображение Hero рендерится сервером, браузер начинает его загружать немедленно, без ожидания JS.
- **CLS** — `next/image` резервирует место под картинку ещё до её загрузки (обязательные `width`+`height`), поэтому
  layout-сдвига нет.
- **FID / INP** — клиентский JS минимален: большинство компонентов — Server Components, `'use client'` только у листовых
  интерактивных элементов.

**Prefetch без waterfall.** Данные из API фетчатся один раз на сервере (`Promise.all` в `page.tsx`), сериализуются через
`HydrationBoundary` и передаются клиенту как JSON. Клиентский `useSuspenseInfiniteQuery` читает кеш синхронно — никакого
дополнительного сетевого запроса при гидратации.

**Оптимизация изображений из коробки.** `next/image` автоматически конвертирует в WebP, генерирует `srcset` под разные
DPR и откладывает загрузку (`loading="lazy"`) для изображений ниже fold.

**Метаданные.** `export const metadata` в `layout.tsx` / `page.tsx` генерирует `<title>`, `<meta description>`,
OpenGraph и структурированные данные на сервере — без клиентских библиотек.

### Как получить похожий результат на React + Vite

Vite по умолчанию производит CSR-бандл. Для достижения сопоставимых показателей потребовалось бы:

| Требование              | Решение на React + Vite                                                                                                                                     |
|-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------|
| SSR HTML                | Самописный Express/Fastify-сервер с `renderToString` / `renderToPipeableStream` из `react-dom/server`; или `vite-plugin-ssr` / `Rakkas` как готовая обёртка |
| SEO-мета-теги           | `react-helmet-async` — управляет `<head>` как на сервере, так и на клиенте                                                                                  |
| Оптимизация изображений | Ручная настройка Sharp на сервере + самостоятельная генерация `srcset`; либо внешний CDN с трансформациями (Cloudinary, imgproxy)                           |
| Prefetch без waterfall  | Ручной `fetchDehydratedState` на сервере + `HydrationBoundary` из TanStack Query                                                                            |
| CLS = 0                 | Явное задание `width`/`height` или `aspect-ratio` в CSS для каждого изображения                                                                             |

Это реализуемо, но требует значительно больше инфраструктурного кода и времени. Next.js предоставляет те же возможности
в виде соглашений из коробки.

## Структура данных — Server + Client без waterfall

```
page.tsx (Server Component)
  └── Promise.all([prefetchInfiniteQuery × 3])   ← один запрос к API на сервере
        └── HydrationBoundary state={dehydrate(queryClient)}
              ├── ProductSection ('use client')
              ├── EmployeeSection ('use client')
              └── ReviewSection ('use client')
```

Серверные секции (Hero, About) не делают запросов вовсе — они используют статические данные из `data.ts`.

---

## Разделение Server / Client Components

| Секция   | Тип    | Причина                                             |
|----------|--------|-----------------------------------------------------|
| Header   | Server | Статика + nav, нет интерактивности                  |
| Hero     | Server | Статический контент                                 |
| Product  | Client | `useSuspenseInfiniteQuery` + кнопка «Загрузить ещё» |
| Employee | Client | `useSuspenseInfiniteQuery` + кнопка «Загрузить ещё» |
| About    | Server | Статические карточки преимуществ                    |
| Review   | Client | `useSuspenseInfiniteQuery` + Embla-карусель         |
| Footer   | Server | Статика                                             |

`'use client'` граница проходит по `*Section`-компонентам — все вложенные карточки и элементы остаются обычными
функциями без директивы.
